# Keep Companion tools current and relationship state workspace-owned

Status: proposed

Codex thread metadata snapshots dynamic tool definitions, which made imported threads lose CFL tools and would make old threads retain stale schemas. CFL instead exposes its relationship, dice, and bounded `list_photos` discovery capability through a workspace-configured Companion MCP, while an append-only `.lamplit/relationship.jsonl` Relationship Journal remains the sole relationship source of truth and the MCP server its only runtime writer. The photo listing reads the same metadata-only Conversation Image Catalogue as the Human gallery: Human-sent, Agent-generated, and restored historical conversation images. Native inspection of a returned path does not write it. CFL reads these projections for UI and context; Codex conversation history records tool activity but owns neither the current tool catalogue nor relationship state. Affinity movement is bounded to ±10 per update call, avoiding private Codex turn metadata and cross-process coordination.
