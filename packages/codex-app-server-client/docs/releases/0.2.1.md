# 0.2.1 release guide

Target: `@jaminzhou/codex-app-server-client@0.2.1`, non-preview, intended npm tag `latest`.
This document describes the candidate and its release gates, not proof of publication.

```bash
npm view @jaminzhou/codex-app-server-client@0.2.1 version --registry https://registry.npmjs.org/
npm install --save-exact --ignore-scripts --include=optional @jaminzhou/codex-app-server-client@0.2.1
node node_modules/@jaminzhou/codex-app-server-client/examples/stream.mjs
```

## Scope and migration

This maintenance release retains the `0.2.0` public API, generated protocol, dependencies and
transport behavior. Codex remains pinned to `0.154.0`; default initialize client-info metadata
now reports `0.2.1`. No consumer code migration is expected from `0.2.0`. Consumers moving from
`0.1.0` must still read the [0.2.0 API migration notes](../api-diff-0.2.0.md).

The change is to repository release tooling: bounded read-only retries for temporary npm
visibility lag, strict mismatch failures, regression tests and publishing timeout headroom.
The scripts/workflows are not shipped SDK retry behavior. Publication is never retried
automatically. See [trusted publishing](../trusted-publishing.md).

Node.js 18+ ESM installation and the exact basic runtime matrix (`0.150.1`, `0.152.1`,
`0.153.4`, `0.154.0`) remain unchanged. Source builds use Node.js 22+ / pnpm 11.7.0.
This is still a pre-1.0 client, not a browser SDK or a complete app-server UI.

## Release gates

1. Review the version/docs changes, run `pnpm check` and current-head cross-platform CI,
   including Git and installed-package checks. Obtain fresh post-push bot review, resolve
   actionable bot findings, merge only with authorization and verify post-merge main CI.
2. Prepare a clean immutable candidate with `npm-release-candidate.yml` for `0.2.1`. Require
   compatibility, upstream drift, and exact npm/pnpm archive consumer checks. Retain the
   successful run's archive and evidence separately from historical approved artifacts.
3. Present the exact version, source SHA, candidate run ID, SHA-512 integrity and intended
   `latest` tag to Jamin for final publication approval. Do not rebuild approved bytes.
4. Acceptance is deterministic real-runtime/local-provider and scripted RPC testing: 19
   examples plus four CLI input cases. It does not establish fresh real-account, OAuth,
   biometric or model-quality acceptance. Earlier live-account evidence remains historical;
   any new live-account test requires separate scoped authorization.
5. Publish only the approved retained archive through the configured main-restricted OIDC
   workflow. Verify all registry tags, dependencies and downloaded-byte integrity, then
   fresh exact-version npm/pnpm registry consumers. Retain the complete publication receipt.
   Only a successful full run establishes the corrected automated publication chain.

The prior `0.2.0` npm publish succeeded, while its immediate registry read-back failed and
consumer verification was completed separately. That historical run remains failed; neither
this release guide nor a green ordinary CI run retroactively changes it. Never republish
`0.2.0` or rerun its publish job to validate this fix.

Detailed commands and recovery boundaries are in [RELEASING.md](../../RELEASING.md).
