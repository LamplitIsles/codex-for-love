# 0.2.0 release guide

Target: `@jaminzhou/codex-app-server-client@0.2.0`, non-preview, intended npm tag `latest`.
This document also ships in local candidates. It describes scope and release gates, not proof
that publication has happened. Check the exact public registry version before installing.

```bash
npm view @jaminzhou/codex-app-server-client@0.2.0 version --registry https://registry.npmjs.org/
npm install --save-exact --ignore-scripts --include=optional @jaminzhou/codex-app-server-client@0.2.0
node node_modules/@jaminzhou/codex-app-server-client/examples/stream.mjs
```

If unavailable, use an explicitly verified local candidate or choose an older release with its
documented feature set. Do not substitute the unrelated unscoped package or republish `0.1.0`.

## Scope

- Bundled Codex `0.154.0` and matching generated public protocol: 162 typed raw methods,
  159 validated response methods, 83 notification methods and 11 server-request methods.
- `ExternalMessage` with tool-level authority, independent joined-turn consumers and
  deterministic race, interruption, approval-inheritance and process-failure regressions.
- Sixteen numbered Node equivalents of the public Python SDK examples plus the three safety
  examples. The local fixture suite does not call a model service or use user credentials.
- Node.js ESM for local Node hosts / Electron main processes. Installed Node 18+ compatibility
  is retained; prefer maintained Node. Source builds need Node 22+ / pnpm 11.7.0.
- Runtime tests for four exact Codex versions; rich workflows use the bundled runtime.
  This is not a browser SDK, complete UI, automatic replay implementation or 1.0 stability promise.

Read [migration notes from 0.1.0](../api-diff-0.2.0.md) before changing wrappers around turn input
or exhaustive protocol-union handling. Native verification is raw protocol coverage only; no
biometric UI, credential enrollment or automatic approval behavior is added by this client.

## Release gates

1. Reviewed release source: version, changelog, installation commands, API diff and support policy
   agree; `pnpm check`, package/Git consumers and cross-platform current-head CI pass.
2. Fresh post-push bot review with no actionable unresolved threads, authorized merge and
   post-merge main CI. No stale review or previous source's CI substitutes for these checks.
3. Final artifact: run `pnpm release:pack` from the intended clean committed source. Retain
   `artifacts/jaminzhou-codex-app-server-client-0.2.0.tgz` and its `release-evidence.json` with
   exact source SHA, `sourceDirty: false`, SHA-512 integrity and npm/pnpm consumer verification.
   Archive the old evidence before preparation. Do not rebuild the selected bytes at publication.
4. Acceptance boundary: deterministic real-runtime/local-provider tests and scripted login/native
   verification contracts are the automatic evidence for this release. Fresh real-account,
   OAuth and biometric acceptance is not established; earlier `0.1.0` acceptance is historical,
   since executable and runtime bytes changed. Disclose this scope when requesting publication
   approval. Any new live test needs a separately approved account, exact artifact, empty workspace,
   permitted operations, model/usage budget and deadline; it is never run automatically.
5. Publication: Jamin approves the exact version, artifact integrity, `latest` tag and disclosed
   acceptance scope. Confirm authorized npm access/2FA or the explicitly configured
   [trusted publisher](../trusted-publishing.md); publish only the retained archive with
   `--ignore-scripts`. Preparing or merging the PR does not grant publication authority.
6. Read back version, all dist-tags and registry integrity; download the published archive, compare
   it with the approved bytes, then repeat fresh npm and pnpm installed-consumer checks. Record
   publication separately from candidate evidence; only then report the release as complete.

Detailed commands and failure handling are in [RELEASING.md](../../RELEASING.md).
The [0.1.0 release record](./0.1.0.md) remains an immutable historical reference.
